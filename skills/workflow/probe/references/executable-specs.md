# Executable Specifications

Optional techniques you may cite when you turn a deliverable into an executable specification. None is required, and none locks a tool or a language.

- **Given-When-Then and ATDD.** Write each scenario as a Given state, a When action, and a Then observable result. Acceptance-test-driven development turns the scenario into a failing test before the code exists.
- **Tracer bullet.** Named in "The Pragmatic Programmer" by Hunt and Thomas. One thin slice that runs end to end proves the path before the work widens.
- **Definition of Done.** One shared quality bar that applies to every phase, kept apart from the per-phase acceptance criteria.
- **Executable forms.** Turn a testable scenario into whatever executable form the project's language supports: a BDD feature file, a contract test, or a property test. The form matters more than the runner.

Cite a technique by name. Do not add a step for it, and do not make the plan depend on a tool.
